## 四、Git 协作规范（多人同时改代码时必看）

1. **不要直接改 `main` 分支**。每个人开自己的分支：
   ```bash
   git checkout -b feat/你的名字-模块名     # 例如 feat/zhangsan-preprocess
   ```
2. 提交信息写清楚做了什么（中文没问题）：
   ```
   feat: 增加 IQR 异常值处理
   fix: 修正标准化在测试集上的数据泄漏
   docs: 补充 EDA 结论
   ```
3. 推送自己的分支并发起 Pull Request：
   ```bash
   git add .
   git commit -m "feat: 完成缺失值填充逻辑"
   git push -u origin feat/你的名字-模块名
   ```
4. 别人 review 后再合并到 `main`，避免互相覆盖。
5. **动手前先拉取最新代码**：`git pull --rebase origin main`。
6. 数据文件不要提交（已在 `.gitignore` 排除），大文件走网盘共享。

## 五、常见冲突处理

- 如果 `git pull` 提示冲突：打开冲突文件，按 `<<<<<<<` / `=======` / `>>>>>>>` 标记手动选择保留哪部分，然后
  ```bash
  git add 冲突文件
  git rebase --continue
  ```
- 实在搞不定时，先备份自己的文件，再 `git checkout -- 文件` 放弃本地修改重来，比强行合并更快。
