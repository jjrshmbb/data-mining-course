# ImAD后续复现清单

本文件是计划与实现成本核查，尚未执行方法训练。

## 已核实的实现条件

官方提交为a4963fc976fbb10759717dd6afea51320a5d2639。README提供Arrhythmia示例，但安装行写为pip install requirements.txt，缺少-r。requirements包含大量file:///croot及Linux构建路径，不能直接用于Windows。

官方main.py在检测不到CUDA时选择CPU。当前没有安装与验证其深度学习环境，也没有测得训练耗时或显存。不能据此声称本机已满足全部方法运行条件。

配置arguments/arrhythmia.json给出30 epochs、batch_size=256、latent_dimension=128、lr=0.0001等值，部分字段由命令入口补充。训练器涉及SinkhornDistance，内部最大迭代数为1000，实际收敛与耗时尚需测量。

## 优先迁移步骤

1. 在独立的ImAD环境中确认torch、必要的torchvision、click、scipy、numpy、scikit-learn和项目实际import集合。不要将官方完整Linux冻结环境照搬，也不要污染当前基础实验环境。
2. 固定官方提交，记录每项适配改动。先用CPU、默认Arrhythmia、一种缺失率和一个种子跑完整训练；不按测试集表现选择epoch、随机种子或超参数。
3. 检查训练/测试标签数量及特征维数，核对数据划分、归一化、缺失掩码和评价计算。当前基础实验0/10/30%的条件与论文主表20/50%不同，需要独立的论文对照配置。
4. 区分原始实现复现和统一评估适配。原始复现尽量保留官方算法；统一比较再将数据索引与掩码注入同一协议。每项差异单列，不混报成绩。
5. 确认论文AUPRC计算与本项目AP的关系，必要时同时保存两种明确定义的指标。不能仅因名称相似就直接对表。
6. 首次运行成功后补重复实验和训练曲线，并记录CPU/GPU、实际耗时与失败。随后决定是否扩大数据规模。

## 预估与收缩

传统流程的当前实际耗时已在CSV中记录。ImAD迁移预计需要数个工作环节，这只是工作量判断，训练速度尚不可预估。第一至二周优先完成它，不同时增加其他深度方法。课程中的“实现近三年论文任务”必须以实际训练与评价产物验收。
