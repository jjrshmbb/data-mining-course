## 一、这个项目在做什么

真实世界的表格数据几乎都有缺失。业界处理它的标准做法是「先填补、再检测」——用统计量或邻居把空格补上，再交给异常检测器。

**但没有人告诉你：缺失到什么程度之后，这套流程的结果就不能信了。**

本项目把这件事做成一次受控实验：固定数据、固定划分、只改缺失比例与缺失布局，观察四条「填补 × 检测」流程的表现如何变化。

**一句话版本**：一叠体检报告，有些格子被涂黑了。我们想知道——在这种情况下，从这叠报告里挑出病人的本事还剩几成；以及**在没有标准答案时，能不能自己判断这次挑得靠不靠谱**。

## 三、快速开始

```bash
# 环境：Python 3.11，依赖见 requirements-research.txt
# 本项目在 Windows + PyCharm 下验证通过

# 1. 最小验证（1 个种子、完整数据、中位数 + Isolation Forest，约 5 秒）
python run_smoke.py

# 2. 主实验（3 种子 × 5 缺失率 × 2 填补 × 2 检测器 = 60 组，约 1 分钟）
python run_baseline.py

# 3. 缺失布局对照（分散 vs 集中，48 组，约 1 分钟）
python run_block_missing.py

# 4. 分数尺度诊断（只读已有预测分数，不重新训练，约 5 秒）
python analyze_score_collapse.py

# 5. 协议自检（6 项防泄漏检查）
python verify_protocol.py
```

每次运行都会在 `reports/runs/<时间戳>_<标签>_<随机串>/` 下新建目录，**不会覆盖历史结果**。最新一次运行的位置记录在 `reports/latest_run.txt`。

> 在 PyCharm 中：打开项目根目录 → 选择系统 Python 3.11 解释器 → 右键任意 `run_*.py` → 运行，无需命令行参数。

## 六、实验设计

### 划分

遵循 ImAD 官方代码 `split=1` 的数量规则：从 386 条正常样本中取 **320 条训练**，剩余 **66 条正常 + 全部 66 条异常**作为测试（共 132 条，异常率 50%）。

- 训练集**只含正常样本**（正常样本训练协议），标签仅用于构造该协议与最终评分，不进入任何拟合。
- 论文未发布固定索引，本项目重新生成并保存划分索引，**不声称复现论文划分**。
- 三个种子（42 / 2026 / 3407）各自独立生成划分。

### 缺失模拟

- 机制：**MCAR**（完全随机缺失），逐元素独立伯努利采样，同时遮蔽训练与测试特征。
- 比例：0% / 10% / 30% / 50% / 70%。
- **嵌套掩码**：同一随机流按不同阈值截断，10% 的位置一定包含在 30% 中，30% 一定包含在 50% 中——各档位之间唯一的差别是「涂得更多」，而不是「涂在别处」。
- **掩码共享**：同一 (种子, 缺失率) 下，四条流程复用完全相同的掩码，掩码的 SHA256 记录在结果表中。
- 掩码生成函数只接受矩阵形状与种子，**不接受标签**。

### 预处理顺序

```
训练/测试特征 → StandardScaler（仅训练集拟合，忽略 NaN）
              → 填补器（仅训练集拟合）
              → 检测器（仅训练集拟合）
              → 测试集只做 transform 与评分
```

**先标准化、再填补**，这样 KNN 填补的距离不会被大数值列主导。两种填补走完全相同的顺序，保证可比。

### 四条流程

| 填补                 | 检测器              | 参数                            |
| ------------------ | ---------------- | ----------------------------- |
| 中位数（SimpleImputer） | Isolation Forest | 200 棵树，`contamination='auto'` |
| 中位数                | LOF              | 20 邻居，`novelty=True`（只对新样本评分） |
| KNN（KNNImputer）    | Isolation Forest | 5 邻居，均匀权重                     |
| KNN                | LOF              | 同上                            |

所有模型的 `score_samples` 统一取负号，使**分数越大越异常**。

### 指标

- **AP**（`average_precision_score`）：按可疑度排序后，头部精确率的加权平均。
- **ROC-AUC**：随机取一个异常与一个正常，异常分数更高的概率。

**不使用准确率**：测试集异常率为 50%，若异常率降到 1%，全判正常即可得到 99% 的准确率。异常检测中准确率无意义。

⚠️ **AP 的随机基线不是 0，而是测试集的异常比例（本项目为 0.50）**。因此 AP = 0.77 应读作「比随机好 0.27」，**不能读作「77% 准确」**。

### 六项防泄漏自检

`verify_protocol.py` 会自动检查并输出 `protocol_checks.json`：

1. 274 维特征不含标签列，且不存在与标签完全相同的列
2. 训练集只含正常样本；训练与测试不重叠且并集为全集
3. 掩码可复现，且嵌套、不依赖标签
4. AP 与 ROC-AUC 的分数方向一致（越大越异常）
5. 改动任意一条测试样本，不会影响其他测试样本的分数（四条流程分别验证）
6. 同一 (种子, 缺失率) 下所有方法共用同一掩码；0% 缺失时两种填补结果完全一致

## 七、主要结果

### 缺失比例的影响

来源：`reports/runs/20261025_235821_baseline_46f29e/summary.csv`（3 种子均值）

| 缺失率 | knn+IF | knn+LOF | 中位+IF  | 中位+LOF |
| --- | ------ | ------- | ------ | ------ |
| 0%  | 0.7673 | 0.7147  | 0.7673 | 0.7147 |
| 10% | 0.7771 | 0.7351  | 0.7670 | 0.7355 |
| 30% | 0.7780 | 0.7456  | 0.7729 | 0.7450 |
| 50% | 0.7699 | 0.7652  | 0.7701 | 0.7642 |
| 70% | 0.7637 | 0.7588  | 0.7701 | 0.7579 |

**观察**：

- 全程**没有出现单调下降**，AP 区间为 0.7147–0.7780。
- **LOF 随缺失率上升**：0.7147 → 0.7652（50%），升幅约 0.045。
- **两个检测器的差距被抹平**：0% 时 IF 高 0.053，70% 时只高 0.005。
- 耗时：KNN 填补在 50% 缺失时约 0.44 秒，中位数填补约 0.15 秒；**但 AP 并未相应提升**。

### 缺失布局的影响

来源：`reports/block_missing/20261026_000146/layout_contrast.csv`

两种布局的**缺失单元总数精确相等**；集中布局把缺失全部塞进随机选中的 137/274 列（列内缺失率 20% / 60%），选列只用随机数、不看标签。

| 缺失率 | 流程      | 分散     | 集中     | 差值      |
| --- | ------- | ------ | ------ | ------- |
| 10% | knn+IF  | 0.7740 | 0.7675 | −0.0066 |
| 10% | knn+LOF | 0.7192 | 0.7201 | +0.0010 |
| 10% | 中位+IF   | 0.7643 | 0.7694 | +0.0051 |
| 10% | 中位+LOF  | 0.7204 | 0.7226 | +0.0021 |
| 30% | knn+IF  | 0.7736 | 0.7688 | −0.0048 |
| 30% | knn+LOF | 0.7260 | 0.7359 | +0.0100 |
| 30% | 中位+IF   | 0.7736 | 0.7677 | −0.0059 |
| 30% | 中位+LOF  | 0.7255 | 0.7379 | +0.0124 |

**观察**：差值全部落在 −0.007 ~ +0.012，方向不一致（两正两负），量级小于种子间标准差。**在总量相同时，把缺失集中到一半的列上，几乎没有影响。**

### 分数尺度诊断

来源：`reports/score_collapse/20261025_235821_baseline_46f29e/summary.csv`（只读取已保存的预测分数，不重新训练）

| 流程      | AP 0% → 70%     | 分数离散度（相对 0%） | 并列比例 |
| ------- | --------------- | ------------ | ---- |
| 中位+IF   | 0.7673 → 0.7701 | **0.51**     | 1.00 |
| knn+IF  | 0.7673 → 0.7637 | **0.53**     | 1.00 |
| 中位+LOF  | 0.7147 → 0.7579 | **1.53**     | 1.00 |
| knn+LOF | 0.7147 → 0.7588 | 1.09         | 1.00 |

**观察**：Isolation Forest 的分数离散度降到 0% 时的一半，而 AP 几乎不变；LOF 的离散度反而扩大。由于并列比例始终为 1.00（132 个样本 132 个不同分数），**这是「分数尺度漂移」，不是「排序塌缩」**。

**实践含义**：AP 与 ROC-AUC 只看排序，对分数的绝对尺度完全无感。若下游采用「取分数最高的 1%」，不受影响；若采用「分数超过固定阈值即报警」，则阈值会失效，而所有指标仍显示正常。

## 八、这些结论不能推到哪

1. **只有一个小型数据集**（452 条），3 个种子。表中标准差是种子间样本标准差，**不是置信区间**，量级与效应量相当。
2. **测试集异常率被人为凑成 50%**。AP 的绝对值强依赖异常比例，不能外推到低异常率场景；ROC-AUC 相对稳健，但同样受小样本影响。
3. **只验证了 MCAR 与「50% 列集中」两种缺失机制**。MAR、MNAR、仅测试时缺失、更极端的集中强度均未验证。
4. **274 列没有列名**，无法进行特征层面的解释，也无法做业务意义上的特征工程。
5. 本项目**不构成任何临床或业务结论**。Arrhythmia 的 ODDS 版本对原始医学类别做了合并，分数不代表诊断能力。

## 九、与近期工作的关系

| 工作                                | 做了什么                                            | 它的前提          |
| --------------------------------- | ----------------------------------------------- | ------------- |
| **ImAD**（NeurIPS 2024）            | 指出「填补偏差」——填补模型只在正常数据上训练，会把异常样本填得「太正常」；提出端到端方法缓解 | 需要真值才能衡量偏差大小  |
| **M-DEW**（arXiv 2024）             | 为每条「填补 + 预测」流水线逐样本动态分配权重                        | 需要下游任务的标签计算误差 |
| **SEAOP**（Brief. Bioinform. 2024） | 用扰动下的模型稳定性来挑选异常检测模型                             | 需要在模拟数据上有准确率  |
| **MacrOData**（KDD 2026）           | 2,446 个数据集的表格异常检测基准，非方法                         | 提供评测场地，不提供方法  |

**共同缺口**：以上工作都需要「答案」才能运作，而真实场景往往没有答案。

**本项目的位置**：不用标签，只观察「换个方式再注入缺失，结论还稳不稳」。这是一个**尚未验证的假设**，不是已成立的贡献。
